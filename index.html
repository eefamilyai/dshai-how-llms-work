How a large language model actually works

Every LLM is the same machine: it reads a sequence of tokens and outputs a probability for what comes next. Then it does it again.

The one idea: a model never writes a sentence. It computes a probability for the single next token, picks one, glues it onto the end, and runs again. A 500-word answer is about 700 laps of that same loop.

scroll
01 · the whole pipeline

Eight stages, start to finish

text → tokens → vectors → layers → scores → probabilities → one draw → repeat

Strip away the branding and every model runs the same eight steps. Only two of them hold knowledge — the attention that mixes tokens together, and the feed-forward layer that transforms them. Everything else is plumbing.

02 · tokenization

A model has never seen a letter

a rare word is split into pieces; each piece is an integer id

Every model has a fixed vocabulary — a list of roughly 100,000 to 200,000 entries, numbered from the beginning. Tokenizing is just choosing which entries to use. A word the vocabulary already contains becomes one token. A word it does not contain gets cut apart until every remaining piece is something it has seen before.

So The cat sat is three tokens, but unbelievably is also three — because nothing in the list matches the whole word. Both end up as integers. The model never sees a single letter.

03 · embeddings

Each id becomes a vector

direction carries meaning

The embedding table has one row per vocabulary entry. Meaning lives in the direction of those vectors, which is why arithmetic on them produces sensible neighbours.

04 · attention

The only place tokens talk to each other

each token asks a question; earlier tokens advertise answers

The best matches get averaged in. This is the expensive part: the work grows with the square of context length.

05 · the causal mask

No peeking at the future

everything above the diagonal is masked out

Every score pointing at a later position is set to negative infinity before softmax. That single constraint lets one pass over N tokens produce N training signals — and forces generation to be sequential.

06 · many heads

Dozens of lookups at once

each head learns a different relationship

One attention pattern is not enough, so the model runs many in parallel. One head tracks the previous token; another resolves pronouns; another matches brackets.

07 · where the knowledge lives

Two-thirds of the parameters

the token visits a couple of experts, not all of them

Attention decides what to look at. The feed-forward network decides what to make of it, and holds most of the stored facts. Splitting it into experts lets total size grow while per-token cost barely moves.

08 · depth

The same block, sixty times over

abstraction accumulates with depth

Early layers handle surface form; middle layers build syntax and track entities; late layers hold task state. The same residual stream is edited at every stop.

09 · the output head

One vector becomes every word in the vocabulary

raw scores in, a probability distribution out

The final vector is projected against the whole vocabulary, producing one raw score each. Softmax turns those scores into a distribution that sums to exactly 1.

10 · choosing

The distribution is not the answer

slice area is probability; the needle is one draw

Temperature sharpens or flattens the curve; top-k and top-p cut off the tail. Then one token is drawn, appended to the input, and the whole machine runs again.

11 · the KV cache

The memory that makes generation possible

every new token adds one full column across every layer

Keys and values for every previous token are computed once and kept. Without that cache, each new token would re-read the entire conversation. It grows linearly with context and dominates memory cost.

12 · how it learned

Predict the next token, then nudge

predict → measure the error → nudge every weight → repeat

No labels, no supervision — the training signal is simply the next token in the document. A forward pass predicts every position at once; a backward pass assigns blame; every weight moves slightly downhill.

13 · where the cost is

Three lines that blow up

attention O(n²) · cache O(n) · prefill O(n·L)

Compute, memory, and the bandwidth to move that memory. Every serious long-context design is a response to one of these three lines — which is exactly the frame for Part 2.
