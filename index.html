How a large language model actually works

Strip away the branding and every LLM is the same machine: it reads a sequence of tokens and outputs a probability for what comes next. Then it does it again. This page walks the entire path — once, slowly, with pictures.

The one idea: a language model never "writes a sentence". It computes a probability distribution over its entire vocabulary for the single next token, picks one, glues it onto the end of the input, and runs again. A 500-word answer is ~700 trips around that same loop.

02 · Tokenization

Text becomes integers

A model has never seen a letter. It only ever sees IDs.

The tokenizer is a fixed, non-neural algorithm. It splits text into tokens — frequent words whole, rare words into pieces, punctuation and whitespace attached to what follows — and maps each to an integer from a fixed vocabulary of roughly 100k–200k entries. The model's entire input and output world is that list of integers.

Type anything below to see the shape of it. (This demo uses a simplified splitter with deterministic fake IDs — a real byte-pair encoder would differ in the exact cuts, but the feel is the same: common things get one token, rare things get chopped.)

why it matters

Context length is measured in tokens, not words or characters. English averages ~1.3 tokens per word; code, JSON, and non-Latin scripts are far worse. A "1M-token context" is roughly a 750,000-word book.

why it's brittle

Models famously miscount letters in words because they never see letters — only whole-chunk IDs. strawberry might be one token, or three, and the model has no idea which characters are inside.

why it costs

Every token you send must be processed by every layer, and every token the model generates must be stored in the KV cache. Tokens are the unit of money, latency, and memory.

03 · Embeddings

Each ID becomes a vector

An embedding table is a lookup: row 4711 in, a 4096-number vector out.

The embedding matrix is a giant learned table with one row per vocabulary entry. Looking up a token is just indexing a row. That vector — typically 2,000 to 8,000 numbers wide — is the token's starting representation, and everything downstream edits it.

token "cat" → ID 4711 → row 4711 of the embedding table
…4,096 numbers, each learned. Direction encodes meaning: similar words end up pointing in similar directions, which is why king − man + woman ≈ queen works.

Position also matters. "dog bites man" and "man bites dog" contain identical tokens. A positional signal — sinusoidal encodings, learned positions, or RoPE — is added or injected so the model knows the order. Nearly every modern model uses some form of rotary position embedding (RoPE), which rotates the query and key vectors by an angle proportional to position. Hold on to that: V4.1's FP4 cache quantizes after RoPE, and that detail turns out to matter.

04 · The residual stream

One highway runs through the whole model

Blocks do not pass data along a chain. They read from and write to a shared bus.

Picture a single wide vector — the residual stream — running from the embedding layer to the output. Each transformer block reads it, computes something, and adds the result back. Nothing is overwritten. The stream accumulates.

Embedding → residual streaminitial write
Block 1+ attention, + MLP
Block 2+ attention, + MLP
… 60 more …additive
Final normclean up
Unembedding → logitsread out

This "additive" design is why deep models train at all: gradients have a clean, short path to every layer. It is also why the residual width is a natural place to innovate — DeepSeek V4 introduced hyper-connections, widening this stream into several parallel lanes, and V4.1 refined them into Single-Pass mHC.

05 · Self-attention

The only place tokens talk to each other

Each token asks a question, every earlier token advertises an answer, and the best matches get averaged in.

Attention is a lookup. For each token the model computes three vectors by linear projection:

Query — Q

"What am I looking for?"

Key — K

"What do I offer?"

Value — V

"What do I actually hand over if chosen?"

The score between a query and a key is their dot product. High dot product = good match = high weight. Softmax turns the scores into weights that sum to 1, and the output is the weighted average of the values.

Attention(Q, K, V) = softmax( Q · Kᵀ / √d ) · V

See it work

Click any token. The bars show how much that token pulls information from each earlier token. These weights are hand-drawn to show the phenomenon — a real head learns its own pattern, and different heads learn different ones.

This is the expensive part. Every token must be scored against every earlier token. Double the context and you quadruple the work — O(n²). At 1M tokens a full attention matrix would have a trillion entries. Almost every efficiency technique in modern LLMs, V4.1 included, exists to avoid computing that matrix.

06 · Causal mask

No peeking at the future

A triangular mask forces each position to attend only to itself and what came before.

The model is trained to predict the next token, so it must not be allowed to see the next token. Before softmax, every score pointing at a later position is set to −∞, which becomes exactly 0 after softmax. The result is a lower-triangular pattern.

Rows = the token doing the looking. Columns = the token being looked at. Amber = self, blue = visible past, dark = masked out. This is why LLMs can generate left-to-right but cannot revise a token they already emitted.

Why it's called "causal"

The mask enforces causality: information flows only forward in time. That single constraint is what lets one forward pass compute a training signal for every position simultaneously — you get N predictions from one pass over N tokens, because none of them cheated.

It is also why prefill (processing your prompt) can be done in parallel while decode (writing the answer) must be strictly sequential. Everything in section 13 follows from this triangle.

07 · Multi-head attention

Many lookups at once, in parallel subspaces

One attention pattern is not enough. So the model runs dozens, then concatenates.

Instead of one Q/K/V set, the model splits the vector into heads — typically 32 to 128. Each head has its own projections and learns a different relationship. One head tracks the previous token; another resolves pronouns to their antecedents; another matches brackets; another links a verb to its subject. Their outputs are concatenated and projected back down to the stream width.

Each square is a small attention matrix for one head — the x-axis is the token doing the looking, the y-axis what it looks at. Bright cells are strong links. Real models learn patterns with this much variety. Grouped-query attention (GQA) and multi-head latent attention (MLA) shrink how many distinct K/V heads must be stored — the first of three multiplicative ways to cut attention cost, and the one V4.1 keeps while attacking the other two.

08 · Feed-forward network

Two-thirds of the parameters live here

Attention routes information. The MLP is where most of the stored knowledge sits.

After attention, every position independently passes through a small two-layer network: expand to roughly 4× the width, apply a nonlinearity, project back. It never mixes positions — it is purely per-token processing.

The key–value memory view

Research on interpretability suggests the first MLP matrix acts like a set of keys — pattern detectors that fire on specific features — and the second matrix like the values they write into the stream. Recalling a fact is a soft lookup, not a database query, and it costs a full matrix multiply every time.

Why sparsity appeared

Because the MLP holds most of the parameters, it is the natural place to add Mixture-of-Experts: split it into many parallel experts and route each token to only a couple. Total parameters balloon while per-token compute barely moves. DeepSeek's models are all MoE — V4.1-Flash has 552B backbone parameters but activates 8B during prefill.

Note the split of labour: attention decides what to look at; the MLP decides what to make of it. Attention is O(n²) in sequence length, the MLP is O(n) but very wide. That division explains why long context is an attention problem and model capability is largely an MLP-and-depth problem.

09 · Depth

Stack that block 60–120 times

Each layer refines the representation; depth is where abstraction comes from.

A transformer is not a clever architecture so much as a simple one repeated to an extreme degree. Early layers handle surface patterns and local syntax; middle layers build syntax trees and entity tracking; late layers hold task state and abstract semantics. The same residual stream is edited at every stop.

Layers 1–15surface form, token identity
Layers 16–40syntax, coreference, local semantics
Layers 41–70entities, facts, reasoning chains
Layers 71–90task state, output formatting

Two consequences worth holding onto:

  • Cost scales linearly with depth. A 100-layer model does 100 blocks of work per token. Truncating the work means truncating the depth you have to run — which is exactly what V4.1's encoder-decoder split does at prefill time.
  • Depth and cache are different axes. You can cut the number of layers that must run, or cut the amount of state each layer must keep. V4.1 does both, separately.
10 · The output head

One vector becomes 200,000 scores

The last position's vector is projected against every vocabulary entry.

Take the final residual vector at the last position only — the earlier positions are discarded at inference — normalize it, and multiply by the unembedding matrix. The result is one raw score, a logit, for every token in the vocabulary. Softmax converts the whole set into probabilities that sum to 1.

Only the last position matters for generation. The other N−1 positions did their work during training, providing extra supervised signals for free.

11 · Sampling

Choosing the token

The distribution is not the answer. The answer is one draw from it.

Greedily taking the top token every time produces fluent, repetitive, brittle text. Real systems reshape the distribution first, then draw from it. Move the sliders.

1.00

temperature

Divides the logits before softmax. Below 1 sharpens the distribution (more deterministic); above 1 flattens it (more surprising). At 0 it is pure argmax.

top-k

Keep only the k highest-probability tokens and renormalize. A hard floor on nonsense — but a fixed k is wrong for both peaked and flat distributions.

top-p (nucleus)

Keep the smallest set of tokens whose probabilities sum to p. Adaptive: narrow when the model is confident, wide when it is unsure. Usually the primary control.

12 · Autoregression

And then you do it all again

Output token → appended to input → whole model re-run → next token.

This is the loop that makes an LLM feel like it is thinking in sentences. It is not. Each pass produces exactly one token and throws away everything except that token and the cached state.

Iteration 1
The capital of France is ▮
The model's top prediction: "Paris" at 96.4%
Iteration 2 — input is now the whole string plus "Paris"
The capital of France is Paris▮
Top prediction: "." at 71.2%
Iteration 3
The capital of France is Paris.▮ → stop token

This is the true bottleneck. A 1,000-token answer requires 1,000 sequential forward passes. You cannot parallelize them — each depends on the last. Long-context work is therefore split between two very different problems: making the prefill of your input cheap, and making each decode step cheap. V4.1's architecture is explicitly a response to both.

13 · Two phases

Prefill and decode are different machines

Prefill is parallel and compute-bound. Decode is sequential and memory-bound.

PREFILL

Read the whole prompt at once

All N input tokens go through the model in a single pass. Because the causal mask forbids looking forward, every position's computation is independent — so this is one big parallel matrix operation. It is compute-bound: the GPU is saturated doing math.

Cost grows with (prompt length × depth). For an agent that re-sends a long conversation on every tool call, prefill dominates the bill entirely.

DECODE

Write one token at a time

Each new token is a separate forward pass through all layers. The math per step is tiny — a single row of the attention matrix — but it must read the entire KV cache from memory. So decode is memory-bandwidth-bound: the GPU spends its time waiting for data, not computing.

This is why shrinking the KV cache raises throughput far more than shrinking the parameter count.

The two levers, named:

Cut prefill cost → run fewer layers on the input.
Cut decode cost → keep less state per token, and reuse what you keep across layers.
DeepSeek V4.1 does the first with CED, and the second with CSA2 and FP4 caching. Part 2 shows both in detail.

14 · The KV cache

The memory that makes generation possible

Without it, every new token would re-read the whole conversation.

Attention needs the K and V vectors of every previous token. Recomputing them each step would make generation quadratic in the number of generated tokens. So they are computed once and stored — the KV cache.

what is stored
Key and Value vectors for every layer, every head, every token so far — plus, in sparse designs, the index structures used to find them.
size
2 × layers × kv_heads × head_dim × tokens × bytes_per_value. It grows linearly with context and is the dominant memory consumer at long context.
where it lives
First in HBM (fast, small, expensive). Long-context systems then offload to host memory or SSD, which turns the problem into one of storage and interconnect bandwidth.
why it is reused
A shared prefix — a system prompt, a document, a conversation history — produces an identical KV cache. Caching it means paying for prefill only once. Agent workloads live or die on this hit rate.

Every byte shaved off a KV entry multiplies across layers × heads × tokens. That is why V4.1's headline number — 890 bytes per token of global KV, a quarter of its predecessor, and an eighth of the persistent footprint — is a bigger deal than it sounds.

15 · Training

How the weights get their values

Predict the next token on trillions of tokens of text. Nudge every weight to be slightly less wrong. Repeat.

There is no supervision, no labels, no human in the loop at this stage. The training signal is simply "the next token in the document" — which is why this is called self-supervised learning, and why it can consume the entire internet.

What emerges

Nothing in this objective mentions grammar, arithmetic, translation, or code. Yet predicting the next token well requires all of them. Capability is a side effect of compression: the model is forced to build whatever internal machinery makes text predictable.

What it costs

Pretraining is measured in GPU-months and megawatt-hours. This is where the "training is the expensive part, inference is the profitable part" split comes from — and why architectures that reduce inference cost are commercially decisive even if they cost more to train.

16 · Post-training

From autocomplete to assistant

A pretrained model completes text. It does not answer questions.

A base model asked "What is the capital of France?" may respond with a list of exam questions, because that is what the pattern looks like on the web. Turning it into something helpful is a separate pipeline.

1 · Supervised fine-tuning (SFT)learn the assistant format from human-written examples
2 · Preference tuning (RLHF / DPO)optimize toward answers humans rate as better
3 · Reasoning / RL on verifiable tasksreward correct math, code, and tool use; learn to think longer
4 · Distillation & effort controlcompress capability, and dial how much thinking a query gets

Test-time scaling. A modern reasoning model spends hundreds or thousands of tokens "thinking" before answering. This buys accuracy with compute — and it is why long context and cheap prefill stopped being academic concerns and became product requirements. The thinking tokens are just more tokens, and they all have to go through the same model.

17 · Where the cost is

Three things blow up with context

Compute, cache memory, and the bandwidth to move that memory around.

O(n²)

Attention compute

Every token scored against every earlier token. Doubling context quadruples the attention work. At 1M tokens this is the reason a naive model cannot function at all.

O(n)

KV cache memory

Linear in context, but with a large constant: layers × heads × dimensions × bytes. It fills HBM, then spills to host memory and SSD, where capacity and bandwidth take over as the binding constraint.

O(n·L)

Prefill work

The prompt passes through every layer once. For agents that resend long histories on every tool call, this is the single largest line item on the bill.

Every serious long-context architecture is a response to one of these three lines. That is the entire frame for Part 2 — the standard transformer above, versus a model built to make all three numbers smaller at once.
